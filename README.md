# Figma2PSD-Pro

一个遵循高内聚、低耦合架构设计的专业级 Figma 导出 Photoshop PSD 插件。

## 项目架构与文件职责

```text
Figma2PSD-Pro
│
├── manifest.json       # Figma 插件清单与权限配置
├── package.json        # NPM 构建脚本与依赖配置
├── tsconfig.json       # TypeScript 编译配置
│
├── src
│   ├── code.ts         # Figma 主线程核心入口（初始化 UI 与监听选择状态）
│   ├── ui.html         # 插件前端界面与 PSD 合成 JS（ag-psd 驱动，构建后复制到根目录）
│   ├── exporter.ts     # 导出主流程控制（离屏快照、独立背景渲染、图层通信）
│   ├── psd-builder.ts  # PSD 数据结构接口定义与类型构建
│   ├── layers.ts       # 树状图层解析（绝对坐标、递归嵌套、组关系判定、类型推断）
│   ├── text.ts         # 文本节点转换（字体预加载、PS 字体名映射、原生 TySh 文本提取）
│   ├── image.ts        # 位图转换（无损 Uint8Array -> Base64 编码管道）
│   └── vector.ts       # 矢量/形状节点混合模式与坐标映射
│
├── code.js             # 构建导出的 Figma 主线程可执行文件
├── ui.html             # Figma 前端 UI（内含 ag-psd PSD 合成逻辑）
└── README.md           # 说明文档
```

## 核心设计与技术亮点

1. **模块化架构**：将 Figma API 操作、文本提取、位图 Base64 转换、图层递归解析和 PSD 结构拼接拆分为独立模块，便于后续维护与扩展。
2. **零污染离屏渲染**：通过 `figma.createRectangle()` 离屏节点单独渲染画板背景，渲染完成后立刻 `.remove()` 销毁，绝对不修改原文档节点显隐属性，保证导出稳定无损。
3. **原生 PSD 可编辑文本**：解析 Figma `TEXT` 节点属性，为 `ag-psd` 注入原生 `TySh` 文本描述符（含 EngineData）。Photoshop 打开后呈现为原生 T 文字图层，支持双击编辑。字体名按 PostScript 风格映射（如 `SourceHanSansCN-Regular`），字号/行距使用磅值、字距使用 1/1000 em，均与真实 PS 导出文件字段对齐。
4. **全量 Viewport 拼合预览流**：写入 PSD 全局 `canvas` 拼合预览，保证画板在 Photoshop 中完美呈现。
5. **图层内容完整可见**：所有图层（含文本图层）均附带导出 PNG 作为栅格像素，配合原生描述符，确保图片与文字在 Photoshop 中都能正常显示。

## 历史问题修复说明（重要）

旧版本导出 PSD 打开后"全是栅格化图层、文字和图片都看不到"，根因有三，均已修复：

1. **ag-psd 版本过旧**：旧版使用 `ag-psd@2.1.0`，该版本明确不支持矢量/文本图层（其 README 声明
   "Does not support vector/text layers"），传入的 `text` 属性被静默忽略，文字图层变成无像素空图层。
   → 已升级为 `ag-psd@31.0.2`（CDN 地址同步更新），完整支持 TySh/EngineData 写入。
2. **图层类型从未被标记**：`layers.ts` 的 `collectNodes` 没有给 `ParsedNodeItem` 写入 `kind` 字段，
   导致 `exporter.ts` 中 `item.kind === 'text'` 恒为 false，所有 TEXT 节点都走了栅格导出分支。
   → 已为 `ParsedNodeItem` 增加 `kind` 并实现 `inferKind()` 类型推断。
3. **图层画布约定不匹配**：ag-psd 2.1.0 的写入器按"文档尺寸画布"读取图层像素，而插件传的是
   "图层自身尺寸画布"，导致图片图层读出越界、被裁剪成透明，全部不可见。
   → 升级后的 ag-psd 31.0.2 采用与插件一致的"图层尺寸画布 + 文档坐标"约定，图片图层像素完整保留。

## 导出问题修复（第二轮）

以下问题会导致导出的 PSD 与 Figma 画面不一致，均已修复：

1. **图层整体错位（阴影/外描边/文字）**：`exportAsync` 默认按"渲染范围"裁切 PNG（含阴影、外描边；
   文字则裁到字形像素），而图层却按布局框 `absoluteBoundingBox` 定位。现在位图图层按
   `absoluteRenderBounds` 定位；文字 PNG 和根画板合成图改用 `useAbsoluteBounds: true`，
   与文本框/画板严格对齐（画板带阴影时 PSD 尺寸也不再变大）。
   **大字号文字（如价格"9999"）在 PS 中整体上移**就是这个原因：旧版文字 PNG 被裁到字形范围，
   却按文本框顶部换算基线，文字上移"框顶到字形顶部"的距离（字号/行高越大偏得越多）。
   现在 UI 端还会校验 PNG 尺寸，若与文本框不符则改用字形渲染范围作为坐标原点，双重保证。
   合成图与画板尺寸因取整相差 1px 时也会自动补齐，不再导致导出失败。
2. **分割线等细线丢失**：水平/垂直线条的布局框高或宽为 0，被当作空节点跳过。现在按渲染范围判断。
3. **子画板/卡片/按钮的底色丢失**：嵌套 Frame/Component/Instance 展开为 PS 组后，自身的填充、
   描边、圆角、阴影没有对应图层。现在为每个有填充/描边的容器离屏渲染一张"xxx 背景"图层。
4. **裁剪内容（Clip content）失效**：超出画板的子内容在 PS 中全部露出。现在为该组加图层蒙版
   （平铺模式下加在各子图层上），完全在裁剪区外的图层直接跳过。
5. **Figma 蒙版（Use as mask）失效**：蒙版形状被当作普通图层显示，被遮罩的图层也没有遮罩。
   现在生成"xxx (蒙版)"组，以蒙版节点像素（Alpha / 亮度）作为组蒙版。
6. **"平铺为独立图层"模式把整个容器拍成一张图**：现在递归展开到叶子图层，只是不建文件夹。
7. **段落文本不换行**：Figma"固定宽度、自动高度"文本被导成 point 文本，PS 中变成一整行。
   现在只有"自动宽度"是 point 文本，其余均为 box 段落文本（自动高度时文本框底部留余量，防止末行被截）。
8. **混合样式文字全部变成 Arial 16 黑色**：同一文本内多种字体/字号/颜色/字距/下划线时，
   现在用 `getStyledTextSegments` 生成完整 styleRuns。
9. **多行 point 文本整体上移**：基线原用末行像素底部推算，现改为按首行计算。
10. **其它文字细节**：百分比字距/行高不再丢失；文字填充透明度叠加到图层不透明度；
    文本大小写（UPPER/SMALL CAPS）映射为 PS 全部大写/小型大写；
    不再对已是粗体/斜体字体再开"仿粗体/仿斜体"（会二次加粗）；
    styleRun 长度按 UTF-16 计数（含 emoji 时不再错位）；水平锚点按文本框而非像素边界。
11. **`figma.getNodeById` 已废弃**：改为 `getNodeByIdAsync`。
12. **构建**：`npm run build` 会同时把 `src/ui.html` 复制到根目录，避免两份 UI 不一致；新增 `npm run typecheck`。

## 对照 PS 原生文件的修正（第三轮）

拿同一设计的「插件导出 PSD」和「PS 原生 PSD」逐层对比后修正：

1. **基线改为 Figma 实测**：Figma API 不提供基线。导出时克隆文本节点到当前页，把内容换成 "H"
   （底部严格落在基线上），读渲染范围底部即得首行基线，测量后立即删除克隆节点。
   不再依赖字体度量表或像素估算（中文字形会略低于基线，像素估算有 1~2px 误差）。
   测量失败或结果异常时自动退回像素检测。
2. **单行的固定宽度文本导出为点文本**：PS 原生稿里的单行标签（价格、时间等）都是点文本。
   旧版把 Figma 固定宽度文本一律导成段落文本（box），首行位置由 PS 自己排，大字号价格会明显偏移。
   现在只有实际多行的文本才导成段落文本。
3. **段落文本框顶部按基线反推**：PS 段落文本首行基线 = 框顶 + 字体 ascent，Figma 是
   框顶 + 半行距 + ascent。现在由实测基线反推 PS 文本框顶部，首行位置与 Figma 一致。
4. **文字预览像素不再被裁掉**：行高小于字号时（如 16px 字、12px 行高），字形会超出文本框，
   按文本框导出 PNG 会把字的顶部/底部裁掉。现在按字形实际范围导出并定位。

## 用 Figma 真实数据校准（第四轮）

通过 Figma API 读取主图画板（节点 12170:4501）每个文字节点的字形渲染范围，结合 PS 原稿中
同字体同字号的字形偏移，反推出 Figma 中每段文字的真实基线（由字形顶部、底部两种推算结果一致，
误差 < 0.1px），用它校准插件：

- 主路径（Figma 内实测基线）：6 段文字误差 0px。
- 备用路径（实测失败时）：改用 Figma 提供的小数精度字形范围，并按字形类型扣除超出基线的部分
  （中文约 0.08em，圆底数字/字母约 0.018em，g/j/p/q/y 扣 descender），误差 ≤ 0.35px
  （原先用整数像素检测约 1px）。
- 居中/右对齐锚点使用未取整的文本框，消除 0.5px 偏差。

回归测试：`node test-env/validate-real-figma-baseline.js`（测试数据在 `test-env/fixtures/figma-12170-4501/`）。

## 组件插槽（Slot）

组件实例中的插槽（Figma 节点类型 `SLOT`）现在会展开为 PSD 组，插槽内的文字保持为可编辑文字图层。
旧版只把 FRAME / GROUP / COMPONENT / INSTANCE / SECTION 当作容器，插槽被整体导出成一张图片。
现在的规则是：凡是有子节点的节点都按容器展开（布尔运算组除外，仍整体导出为一个形状），
以后 Figma 新增的容器类型也不会再被误转成图片。若希望某个插槽/容器拍平为图片，仍可在命名末尾加「-合并」。

### 插槽里读不对的图层（Figma 限制）

实例的插槽内容里再嵌套的图层（例如插槽里放了一个画板，画板里有图标），Figma 插件接口有时读不对：
要么报 "node ... does not exist"，要么返回的其实是外层组件实例本身。这种图层无法单独导出，
插件会把**它所在的那一层容器整体导出为一张图片**（内容不丢），同级的其他图层（如文字）仍正常拆分、可编辑。
导出结果不符合预期时，可在导出完成后点「下载诊断日志」查看插件实际读到的节点树。

## 批量导出多个画板

在 Figma 中同时选中多个画板（Frame / Component / Group 等）后打开插件，列表中会列出全部画板（默认全选，
可逐个取消勾选），点「导出 N 个 PSD 文件」即可**每个画板各导出一个 PSD**。

- 画板逐个处理：一个画板生成并下载完成后再处理下一个，不会因画板多而占满内存。
- 文件名取画板名；重名时自动加「 (2)」「 (3)」，文件名中的非法字符（/ \ : * ? 等）替换为「_」。
- 某个画板失败不会中断整批，结束后在状态栏列出失败的画板及原因。
- 若浏览器/Figma 拦截连续的多文件下载，勾选「打包成一个 ZIP 下载」，所有 PSD 会放进一个 ZIP 一次下载。

## 免手动更新：在 Photoshop 中批量更新文字图层

插件无法在导出时直接生成"已更新"的文字图层：PS 原生文件里的全局文字引擎数据 `Txt2`
（每个字的字形编号、排版结果等）由 Photoshop 文字引擎用本机字体计算，格式私有，
在 Figma 中伪造会导致 PS 仍要求更新甚至文件损坏。因此由 Photoshop 自己完成一次更新并保存，
之后打开、编辑都不会再提示。

**一次性设置（约 1 分钟）**：

1. PS 打开任意一个插件导出的 PSD。
2. 动作面板 > 新建组，命名 `Figma2PSD`；新建动作，命名 `更新文字图层`，开始录制。
3. 动作面板菜单 > **插入菜单项目…**，然后点菜单 **文字 > 更新所有文字图层**，确定。
4. 停止录制。

**之后每次导出**，任选一种：

- **批量脚本**：文件 > 脚本 > 浏览…，选择 `photoshop-scripts/update-text-layers.jsx`，
  再选择存放导出 PSD 的文件夹。更新后的文件保存在其中的「已更新」子文件夹，原文件不变。
- **快捷批处理（拖放即更新）**：先在上面的动作末尾追加"存储"和"关闭"两步，然后
  文件 > 自动 > 创建快捷批处理，选择该动作。以后把导出的 PSD 拖到生成的快捷批处理图标上即可。

脚本会优先执行上述动作；没有设置动作时，会尝试直接调用"更新所有文字图层"菜单命令
（该命令在脚本中的名称未经官方文档确认，不保证在所有 PS 版本可用）。

## 关于 Photoshop「更新文字图层」提示

用 ag-psd 写入的文字图层缺少 Photoshop 内部的排版缓存（ag-psd 文档明确说明无法生成），
所以 PS 打开或编辑时一定会提示更新文字图层，这个提示无法去掉。更新后 PS 会按 PSD 里写入的
「文字原点（锚点 x, 首行基线 y）+ 字体 + 字号」重新排版——这正是本插件精确计算的部分，
因此更新后的位置应与 Figma 一致。为了更接近 PS 原生文件，点文本还会写入：

- `bounds`（排版框）与 `boundingBox`（字形框），均相对文字原点；
- 递增的 `TextIndex`（原先所有图层都是 0）。

用主图画板验证：写入的 boundingBox 与 PS 原稿中同一段文字由 PS 自己排版得出的值相差 < 0.1px。

如果更新后仍有偏移，常见原因是 **PS 所在电脑没安装该字体**（PS 用替代字体排版，度量不同），
更新时 PS 会提示缺失字体。也可在 Figma 插件控制台查看「文字位置对比报告」中每层的定位方法：
`figma-measure`（实测，最准）/ `glyph-bounds`（备用，误差 < 0.4px）。

## 字体映射与"字体缺失"问题

导出的文字图层在 Photoshop 中提示"字体缺失"，通常是因为写入 EngineData 的字体名
（PostScript 名）与你电脑上实际安装的字体名不一致。本项目已内置字体映射机制：

1. **`src/font-map.ts`（自动生成）**：扫描本机已安装字体（Windows 注册表 + 字体文件
   `name` 表），生成 `family/style -> PostScript 名` 的完整映射（含中文字体族名与
   英文名、所有语言变体、TrueType Collection 如 `simsun.ttc`），同时从字体文件的
   `head/hhea/OS/2` 表提取 **ascent/descent 度量**（用于文字基线精确定位）。
   Photoshop 据此能精确定位你本机的真实字体，不再提示缺失。
2. **换机器或增删字体后重新生成**：
   ```bash
   npm run build:fonts   # 重新扫描本机字体并重建 src/font-map.ts（含度量）
   npm run build         # 重新打包 code.js
   ```
3. **查找优先级**：精确匹配 `family+style` -> 归一化模糊匹配（忽略大小写/空格/连字符）
   -> 兜底规则「族名去空格-风格」。
4. 若 Photoshop 仍提示缺失，说明该字体未安装在本机（Figma 云字体需先本地安装），
   或字体映射表未覆盖，请运行 `npm run build:fonts` 重新生成。

## 文字图层定位（"文字往左/下偏移"问题）

Photoshop 打开 PSD 时会执行"更新所有文字图层"，用 TySh 描述符重新排版文字，因此
**图层边界（bounds）不是定位依据，TySh 的 transform 才是**。本项目已对照真实 PS
导出文件修正定位逻辑：

- **基线定位**：`transform` 的平移量 = 文字基线原点，即
  `baselineY = 图层顶 + fontSize × 基线比例`。基线比例来自字体文件度量：
  - 含中文/假名/韩文，或含上升部小写字母（b d f h k l）的文本用 **ascent**
    （CJK 约 0.88em、拉丁约 0.75em）；
  - **纯数字/大写字母文本用 cap height**（如 Arial 0.716、DINPro 0.712）。
    否则 PS 用 ascent 重排后数字会整体下移（数字视觉顶部是 cap height，不是 ascent）。
  旧版本误把基线放在文本框底部，导致文字整体下移。
- **水平锚点**：左对齐锚点在左边、居中对齐在中心、右对齐在右边（旧版本一律用左边，
  导致居中/右对齐文字水平偏移）。
- **TySh text 边界归零**：point 文本的 `text.left/top/right/bottom` 在真实 PSD 中
  全部为 0（旧版本误写成图层边界，干扰 PS 重排版）。
- **box 文本**（Figma 固定宽度文本）：写入精确 `boxBounds`，垂直对齐按 Figma 设置映射。
  **box 文本的 transform 必须用单位阵 `[1,0,0,1,0,0]`**——若 transform 平移量也写
  成 `(left,top)`，Photoshop 会把 transform 位移与 boxBounds 叠加成 **2 倍偏移**
  （实测：期望 (72,702) 却渲染到 (144,1404)）。
- **像素级自检**：导出时对每个文字图层用其 PNG 栅格预览（Figma 逐像素渲染）检测
  文字实际 ink 边界，反推精确基线（无 descender 文本 ink.bottom 即基线），并在
  控制台输出"文字位置对比报告"（Figma 框 / ink 边界 / 度量估算基线 vs 实际使用基线）。

## 字号单位（"PS 点数和 Figma 对不上"问题）

Figma 字号单位是 **px**，Photoshop 是 **pt**（1pt = 1/72 英寸）。为了与设计师在
PS 面板中看到的数值一致，本项目采用以下换算：

- **PSD 内写入的字号 = Figma px 数值**（如 Figma 24px → PSD 24pt），不随导出倍率放大。
- **文档分辨率 PPI = 72 × 导出倍率**（1x→72PPI、2x→144PPI、3x→216PPI），这样
  PS 渲染像素 = pt × PPI/72 = px × scale，与画板像素同步放大，文字相对画板的比例
  在任意倍率下都与 Figma 完全一致。
- 行距（leading）同样与 Figma lineHeight 数值一致；字距（tracking）为 1/1000 em，
  与倍率无关。

## 合并栅格化（命名以「-合并」结尾）

**组 / 组件实例 / 画板**等容器节点，如果**命名以 `-合并` 结尾**，导出 PSD 时会将
**整组拍平栅格化为一张位图图层**，不再展开内部子图层，且图层名自动去掉 `-合并` 后缀。
适用于希望把复杂嵌套结构（组件实例、图标、插画等）直接合并成一张图、避免 PS 中
图层过多或样式失真的场景：

- 子容器（组/组件实例/子画板）：`collectNodes` 识别 `-合并` 后缀后不再递归其子节点，
  该节点以单张 PNG 位图输出，名字去掉后缀。
- 选中的根画板本身命名为 `xxx-合并`：整板直接以一张位图输出（仅合成图 + 该位图图层），
  PSD 文件名同样去掉后缀。
- 不改变原 Figma 文档结构，仅在导出时生效。

> 注意：PSD 合成发生在插件 UI 线程（`ui.html`），其中通过 CDN 加载 `ag-psd@31.0.2`，
> `manifest.json` 已授权 `cdn.jsdelivr.net` 与 `unpkg.com` 网络访问。
